Intégration responsive d'un site existant

Hobbiton™ Movie Set Tours (official version)
HTML CSS JavaScript Responsive Intégration
Contexte

Reproduction fidèle du site officiel de Hobbiton™ Movie Set Tours, réalisée dans le cadre de ma formation.

Mon rôle

Analyser la structure et la hiérarchie de l'information du site, puis l'intégrer en HTML, CSS et JavaScript natif.

Démarche

J'ai relevé l'identité visuelle de la marque (couleurs, typographies, images) pour la respecter scrupuleusement, et pensé la mise en page pour que le site reste lisible et utilisable du mobile au grand écran.

Ce que j'en retiens

Le responsive n'est pas une adaptation de dernière minute : c'est une contrainte à intégrer dès la structure de la page. Ce projet m'a aussi appris à structurer un code propre.

Site e-commerce : Le temps d'une tasse

Brûlerie artisanale de café, thé et infusions (projet fictif)

Projet en cours de développement
UX/UI Figma React Node.js / Express MySQL Docker Responsive
Contexte

Projet de fin de formation (titre DWWM), réalisé en 4 mois : une brûlerie artisanale fictive, installée en Provence, qui veut vendre en ligne. Ses clients sont des particuliers qui aiment le café et le thé et veulent savoir d'où vient ce qu'ils boivent.

Le besoin utilisateur

J'ai écrit 43 user stories par profil (visiteur, client, administrateur), avec des priorités et des critères d'acceptation, puis une arborescence simple : accueil, pages produits, à propos.

Démarche UX/UI

Wireframes sur Figma en niveaux de gris, d'abord en version mobile puis desktop, puis maquettes (charte, logo, composants réutilisables) et prototype cliquable. Je l'ai fait tester à quelques personnes pour repérer les étapes où elles hésitaient ou se perdaient, puis j'ai ajusté les écrans.

Choix d'interface

Le panier est un panneau latéral : l'ajout est confirmé sans quitter la fiche produit. La connexion est une modale, et l'article d'un visiteur non connecté est gardé en mémoire. Les filtres sont cumulables et la sous-catégorie vit dans l'URL : le lien est partageable et le bouton « retour » fonctionne. Des cartes « squelettes » remplacent l'écran vide pendant le chargement.

Identité et accessibilité

Une idée directrice : le café est une pause, une parenthèse dans la journée. Le logo associe une tasse et une horloge. Peu de texte par écran, des couleurs chaudes, des animations discrètes. Texte brun sur crème avec un contraste d'au moins 4,5:1, boutons assez grands pour le doigt, focus clavier visible.

Côté développement

Front-end en React (filtres, modales, panier, appels API), API Node.js / Express en architecture MVC, base MySQL, authentification par jeton JWT dans un cookie HttpOnly, rôles et routes protégées, déploiement avec Docker et Nginx.

État du projet

Le site est encore en cours de développement. Le catalogue, les comptes clients, le panier et l'administration sont en place ; le paiement en ligne est pour l'instant fictif. Prochaines étapes : paiement réel via un prestataire certifié, suivi des commandes côté administrateur et davantage de tests.
